# 标书生成边界约定

> 最后更新：2026-07-02

本文件定义 TenderDoc-Generator 当前线上链路的职责边界。目标是避免模板、Prompt、脚本、知识库和导出器同时抢“格式控制权”。

## 一句话原则

招标文件中的"投标文件格式/响应文件格式"是最高权威。系统只照抄商务格式、填有依据的字段、写技术正文、审查风险；不得生成一套自认为合理的商务格式。**交付商务卷 + 技术卷两卷；报价卷由外部造价软件单独做，本系统不产出。**

## 结构来源

当前结构来源只有三类：

1. 招标文件原始格式页：商务文件的目录、函件、表格、签章位、下划线和附件说明（= 商务卷的来源）。
2. `format_outline_tree`：Parser Agent 提取的格式目录树，用于导航、技术标题收集和人工确认。
3. 人工确认结果：用户在前端确认或修正后的解析 JSON、大纲和资料选择。
4. 技术卷例外：施工组织设计由投标人自行编制，不受招标格式页约束（铁律只约束商务/报价格式）。技术卷目录改为**人工确认驱动 + 招标投标文件格式为准**：
   - Parser 扫招标里的"施工组织设计编制要点 + 附表清单"，逐条原样提取为 `technical_outline`（严禁合并）；
   - 前端中心标签「技术大纲」放出大纲编辑器（含「添加章节」按钮），供人工确认或修正；
   - `_collect_technical_sections` 优先读人工确认后的 `bid_outline_json` 驱动技术卷目录；
   - **大纲退化兜底重建**（`services/workflow_service.py` `_expand_thin_outline`，在逐节知识库检索之前）：当大纲只剩 ≤1 节占位（招标没识别出技术标结构时此前退化成单节"施工组织设计"占位，导致技术卷只一节约 7 页、占比详略与逐节检索全失效）时，自动重建完整大纲。重建优先级：
     - **以招标"投标文件格式"为准**：`_extract_tender_format_structure` 抽"编制要点 + 附表清单"，有招标格式 → `_tender_format_outline` 照招标目录搭（编制要点成章、每张附表逐张补成附表节）；
     - 招标没写明技术标结构 → `_boq_discipline_fallback`（按工程量清单分部分项 + 标准施组章节展开）。
   - **施工方案主体按工程量清单分部分项 → 工序章节拆分**（`_discipline_sections`）：占比越大拆成越多道工序（`_subsection_count`：≥40% 拆 5 节 / ≥25% 拆 4 节 / ≥15% 拆 3 节 / ≥5% 拆 2 节 / 否则 1 节），每道工序单独成节、各跑一次 LLM 调用（突破单节约 5000 字上限）；章节按**施工先后逻辑**排序（`_construction_rank`：路基→排水→路面→桥涵→交安→绿化）——**占比只决定"写多少"、施工逻辑决定"先后"**。用户已确认 ≥2 节真实大纲则原样保留，不重建。
   - 商务卷不参与大纲环节（商务是照抄招标格式、不需在此编辑）。
5. 工程量清单（BOQ）作为技术卷结构与详略的数据源：支持 Excel 上传（`utils/file_parser.py` `extract_text_from_xlsx`，openpyxl 读 .xlsx/.xlsm，旧版 .xls 走 LibreOffice 转换）。上传接口只快速抽存清单全文即返回，不在上传时同步算占比（避免约 30s 同步 LLM 把 DB 连接池抢空）；真实占比改到"开始生成"时再算。

不再作为结构来源：

- 默认模板。
- 公司风格案例。
- 知识库 RAG 片段。
- Generator Prompt 内置目录。
- 离线脚本分析结果。

## 生成职责

| 模块 | 可以做什么 | 不能做什么 |
|------|------------|------------|
| Parser Agent | 提取项目事实、资质、评分项、废标项和 `format_outline_tree` | 决定最终 DOCX 版式 |
| Original Format Service | 从 DOCX/PDF 招标文件复制格式页（PDF 优先经福昕云转可编辑 Word） | 重画表格、改签章位、删下划线 |
| Form Filler | 替换有证据的字段，例如项目名、招标人、投标人、工期、质量 | 编造证号、金额、人员、日期 |
| Content Writer | 在技术正文区域写施工组织方案 | 改商务/报价函件和表格结构 |
| V2 Audit | 挡格式、内容和证据问题 | 为了通过而自动造假 |
| Reviewer Agent | 审废标、资质、报价人工确认和响应性风险 | 代替人工最终盖章确认 |
| DOCX Exporter | 普通 Markdown 排版、图片和表格渲染 | 覆盖招标文件原格式页 |

## 格式处理规则

- DOCX 招标文件：**copy-then-prune** —— 复制源文件后删除格式章范围外的正文元素，保留页眉页脚、图片、表格等关联部件。格式章定位跳过目录(TOC)、取最后一个非 TOC 的格式章标题。
- PDF 招标文件：格式复制走**多档回退链**，从上到下逐档尝试，失败才下沉：
  1. **福昕国内云 PDF→可编辑 Word**（开关 `CLOUD_PDF_CONVERT=foxit`，凭证 `FOXIT_CLOUD_CLIENT_ID`/`FOXIT_CLOUD_CLIENT_SECRET` 在 `.env`）：经福昕 Cloud API 把格式章转成**真·可编辑 Word**（真段落/真表格，非整页贴图），并自动填公司档案字段（投标人/地址/法定代表人/资质等）。接在 Phase 0 格式复制链最上层。**纯文字版招标效果最好，扫描版需先 OCR。**
  2. `pdf2docx`：照抄式转换为 Word。
  3. **整页截图 + 域**：PyMuPDF 渲染格式页整页图片 + 字段域。
  4. **纯整页图**：用 CJK 字体把已知字段烧录进填空横线后转为纯内联图。
  - 四档全失败则**硬报错**——铁律：不输出空壳/近似稿。
- 商务卷只做有依据的字段填空，未知信息保留下划线；未知数值/地名禁止臆造，留【待招标文件确认】占位。
- **商务卷填空与格式体检管线**（`services/cloud_pdf_convert.py`，顺序固定、不得乱插）：
  1. 福昕转换出可编辑 docx；
  2. **填前体检**：`_normalize_split_labels` 理顺福昕切开的两字标签（"性 别"→"性别"）+ `docx_format_doctor.run_format_doctor_prefill` 孤字归位（"性…"+"别："拼回"性别："）——标签完整，后面的空才填得上；
  3. **字段自动填**（只填空格、绝不覆盖已有内容）：公司档案已知字段、基本情况表专项、投标函内联空、授权委托书、成立时间、投标日期、人员组成表、业绩表（选中业绩）、项目经理/总工简历表（选派人员的台账结构化信息）；
  4. **填后体检**：`docx_format_doctor.run_format_doctor(doc, profile)` 格式医生——治填空槽"下划线画一半"等格式病；**铁律：只改格式、绝不改文字**（白名单=profile 里我们填的值，"年/月/日"等招标原文标签绝不误动）；
  5. 清招标红章/原件页码 → `_log_unfilled_fields` 清点未填字段 → 固定字段一致性收尾（公司名错别字纠正等）。
  发现新格式病种 → 往 `docx_format_doctor` 的 healer 注册表加，禁止在转换/填空环节散落打补丁。
- **证据图锚点落位**：证件/业绩扫描图按招标"每样附件插在哪张表后"的要求就地落位（`_ANCHOR_SPECS`：营业执照等→基本情况表后、法人身份证→法定代表人身份证明后、项目经理/总工证件→各自资历表后、业绩证据→类似项目情况表后）；锚点没命中退卷尾兜底，绝不丢图。拟分包表只保留福昕从招标带来的那张，不再注入资料库副本。
- 技术卷由 LLM 独立成文（`_assemble_two_volumes` 单独建文档 + 正奇排版 + 自动更新目录），不追加到商务格式页上，也不做三卷拆分。技术卷目录（TOC）是 Word 域，文件已设打开自动更新域；非 Word 预览软件需手动更新域才显示正确页码。
- **技术卷附表渲染成真表格**（`services/v2_generation_service.py` `_is_appendix_title`/`_appendix_markdown`）：招标规定的附表节（总体作业计划表 / 劳动力计划表 / 临时占地计划表 / 外供电力需求计划表等）**不走 LLM 空写**，而是渲染成标准 Markdown 表格，再由 `markdown_to_docx` 转成 docx 表格；施工总平面图类附表渲染为图占位（提示按招标要求插入图片 / CAD 图 + 文字说明）。这是"招标有表格就要附表格"的落地。
- **技术卷附表逐张装配**（`services/appendix_service.py`）：按招标附表清单逐张定来源——①命中公司定稿附表（`backend/assets/company_appendices/`）原样拼入并自动补"**附表X**"编号（标题带编号→Word TOC 域抓标题→目录与正文页一致）；②否则从招标 PDF 该附表页福昕转可编辑表；③取不到则占位页提示人工。`docxcompose` 拼到技术卷末尾（另起页）；拼接先写临时件校验、再原子替换正式件。
- PDF 原格式路径补内容体检（`_audit_built_format_docx`），防空壳/丢页静默发布。
- 格式复制、技术正文写作失败时，系统必须报错；审查严重问题软阻断并保留失败原因。

## 审查处理规则

V2 内置审查位于 `backend/services/v2_audit_service.py`：

- 格式层：检查表格是否被拍扁、签章位是否丢失、下划线是否保留、图表/图片要求是否落实。
- 内容层：检查施工方案是否过短、是否出现 AI 元话语、金额、身份证号等高风险内容。
- 证据层：检查填入字段是否与公司档案一致，关键字段是否缺失。

工作流审查位于 `backend/agents/reviewer_agent.py`：

- 规则审查覆盖废标条款、资质要求、投标保证金、报价人工确认等。
- 可选 LLM 审查只补充人工可读的风险点，不能覆盖规则审查结论。

## 招标覆盖（防废标）边界

交卷前的最后一道闸，逐条核"评分项是否正面响应 / 废标项是否实质规避"，并入 `full_audit`（`backend/services/v2_audit_service.py` `audit_coverage_layer`，提示词 `backend/prompts/coverage_audit_prompt.py`）。

- **严重度**：废标项漏 = `critical`，评分项漏 = `major`。
- **判定方式**：优先用 LLM 站在评标委员会视角做语义判定（是否针对该条要求给出对应措施 / 承诺 / 数据，而非正文里恰好出现个把关键词）。
- **废标项绝不靠关键词 / bigram 放行**：废标条款原文常被抄进"我方承诺不…"等承诺表里，关键词 / bigram 重合会把真违规误判成"已覆盖"。所以废标项只认 LLM 从严判 True；LLM 不可用 / 解析失败 / 未判到 → 一律按未覆盖处理（铁律：废标宁可误拦不可漏拦）。bigram 仅在 LLM 不可用时**兜底放宽评分项**。
- **当前为告警模式（不硬拦）**：开关 `coverage_audit_block_invalid` 默认 `False`，废标项漏判 `major` 告警而不硬拦。原因：当前废标项里混有"初步评审不通过 / 报价超限价"等规则类条款，任何标书都不会专门写段去响应，硬拦会对每份标误锁死。待废标项按"实质响应类 vs 规则约束类"分类（P1）后再把开关设 `True` 切回硬拦。总开关 `enable_coverage_audit`（默认开）。
- **定向补写**：某节未响应招标要求时，`agents/content_writer_agent.py` `rewrite_node_for_compliance` 重写该节（best-effort），优先把缺口补上而非直接判废。

## 知识库边界

知识库负责提供证据和素材：

- 公司证件、人员证件、业绩、社保、资质、安全生产许可证等作为事实依据。
- 施工方案、组织机构图、进度计划图、施工总平面图等作为技术正文和图片候选。
- 历史中标标书作为风格与质量基线，不作为当前项目格式。

知识库不得改变招标文件目录，也不得把其他项目的人员、证号、金额、电话、日期自动填到当前项目。

## 公司风格案例（已删除）

风格案例库已于 2026-07-03 整体删除：它从未接进技术正文写作提示词，大纲兜底作用也被"按招标格式/工程量清单重建大纲"盖过，属挂名功能。结构与风格的唯一来源=招标文件 + 人工确认 + 知识库素材。数据库 `projects.template_id` 列保留但代码不再读写。

## 交付边界

TenderDoc-Generator 输出：

- 商务卷 DOCX（照抄格式章 + 自动填公司档案字段；福昕开关开时为真·可编辑 Word，否则走 pdf2docx/截图回退）。
- 技术卷 DOCX（人工确认目录 + LLM 施工组织设计正文 + 福昕可编辑附表，独立成文）。
- Markdown。
- 审查报告。
- 资料引用和人工确认点。

**不产出报价卷**：报价（工程量清单）由外部造价软件单独制作，做好后与上面两卷一起进新点软件。

新点投标文件制作软件负责：

- 最终电子投标文件制作（含外部做好的报价卷）。
- CA 签章。
- 加密。
- 上传。
- 平台校验。
