# 标书生成边界约定

本文件定义 TenderDoc-Generator 当前线上链路的职责边界。目标是避免模板、Prompt、脚本、知识库和导出器同时抢“格式控制权”。

## 一句话原则

招标文件中的"投标文件格式/响应文件格式"是最高权威。系统只照抄商务格式、填有依据的字段、写技术正文、审查风险；不得生成一套自认为合理的商务格式。**交付商务卷 + 技术卷两卷；报价卷由外部造价软件单独做，本系统不产出。**

## 结构来源

当前结构来源只有三类：

1. 招标文件原始格式页：商务文件的目录、函件、表格、签章位、下划线和附件说明（= 商务卷的来源）。
2. `format_outline_tree`：Parser Agent 提取的格式目录树，用于导航、技术标题收集和人工确认。
3. 人工确认结果：用户在前端确认或修正后的解析 JSON、大纲和资料选择。
4. 技术卷例外：施工组织设计由投标人自行编制，结构来自标准施工组织设计深度大纲（`construction_plan_outline.py`），不受招标格式页约束（铁律只约束商务/报价格式）。

不再作为结构来源：

- 默认模板。
- 公司风格案例。
- 知识库 RAG 片段。
- Generator Prompt 内置目录。
- 离线脚本分析结果。

## 生成职责

| 模块 | 可以做什么 | 不能做什么 |
|------|------------|------------|
| Parser Agent | 提取项目事实、资质、评分项、废标项和 `format_outline_tree` | 决定最终 DOCX 版式 |
| Original Format Service | 从 DOCX/PDF 招标文件复制格式页 | 重画表格、改签章位、删下划线 |
| Form Filler | 替换有证据的字段，例如项目名、招标人、投标人、工期、质量 | 编造证号、金额、人员、日期 |
| Content Writer | 在技术正文区域写施工组织方案 | 改商务/报价函件和表格结构 |
| V2 Audit | 挡格式、内容和证据问题 | 为了通过而自动造假 |
| Reviewer Agent | 审废标、资质、报价人工确认和响应性风险 | 代替人工最终盖章确认 |
| DOCX Exporter | 普通 Markdown 排版、图片和表格渲染 | 覆盖招标文件原格式页 |

## 格式处理规则

- DOCX 招标文件：**copy-then-prune** —— 复制源文件后删除格式章范围外的正文元素，保留页眉页脚、图片、表格等关联部件。格式章定位跳过目录(TOC)、取最后一个非 TOC 的格式章标题。
- PDF 招标文件：用 PyMuPDF 渲染格式页**整页图片**，按 PDF 页面尺寸放入 DOCX。已知字段（投标人/地址/法定代表人/电话）在转图前用 CJK 字体**烧录进填空横线**（`_bake_fill_values_on_page`）。纯内联图，Pages/LibreOffice/Word/新点都能渲染。**不再用 VML 可编辑文本层或 pdf2docx**（多软件渲染会丢图/错位）。
- 商务卷只做有依据的字段填空（烧录或 OOXML 字段替换），未知信息保留下划线；未知数值/地名禁止臆造，留【待招标文件确认】占位。
- 技术卷由 LLM 独立成文（`_assemble_two_volumes` 单独建文档 + 正奇排版 + 自动更新目录），不追加到商务格式页上，也不做三卷拆分。
- 格式复制、技术正文写作失败时，系统必须报错；审查严重问题软阻断并保留失败原因。

## 审查处理规则

V2 内置审查位于 `backend/services/v2_audit_service.py`：

- 格式层：检查表格是否被拍扁、签章位是否丢失、下划线是否保留、图表/图片要求是否落实。
- 内容层：检查施工方案是否过短、是否出现 AI 元话语、金额、身份证号等高风险内容。
- 证据层：检查填入字段是否与公司档案一致，关键字段是否缺失。

工作流审查位于 `backend/agents/reviewer_agent.py`：

- 规则审查覆盖废标条款、资质要求、投标保证金、报价人工确认等。
- 可选 LLM 审查只补充人工可读的风险点，不能覆盖规则审查结论。

## 知识库边界

知识库负责提供证据和素材：

- 公司证件、人员证件、业绩、社保、资质、安全生产许可证等作为事实依据。
- 施工方案、组织机构图、进度计划图、施工总平面图等作为技术正文和图片候选。
- 历史中标标书作为风格与质量基线，不作为当前项目格式。

知识库不得改变招标文件目录，也不得把其他项目的人员、证号、金额、电话、日期自动填到当前项目。

## 公司风格案例边界

公司风格案例只影响：

- 技术正文深度。
- 正奇常用表达。
- 禁用语气。
- 图表/图片位参考。
- 真实中标标书质量对比。

公司风格案例不影响：

- 商务文件目录。
- 报价文件目录。
- 投标函格式。
- 资格审查表格。
- 签字盖章位置。

## 交付边界

TenderDoc-Generator 输出：

- 商务卷 DOCX（照抄格式章 + 烧录字段 + 合规正文）。
- 技术卷 DOCX（施工组织设计正文，独立成文）。
- Markdown。
- 审查报告。
- 资料引用和人工确认点。

**不产出报价卷**：报价（工程量清单）由外部造价软件单独制作，做好后与上面两卷一起进新点软件。

新点投标文件制作软件负责：

- 最终电子投标文件制作（含外部做好的报价卷）。
- CA 签章。
- 加密。
- 上传。
- 平台校验。
